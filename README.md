# Gm

Gigachad machine

## Состав

| Каталог | Что внутри |
|---------|------------|
| `common/` | `sv.h` — `String_View`; `container.h` — динамический массив ; `logger.h` — `LOG_*` и `PRINT_*` |
| `interface/` | `abi.h` — роли регистров, размеры памяти и стека; `format.h` — функции для работы с заголовками в начале бинарных файлов `.gm`; `opcodes.h` — `enum` со всеми операциями, которые поддерживает VM, и таблица, в которой каждой команде ассемблера сопоставлена сигнатура и опкод |
| `gm/` | `gm.c` — switch по `enum` с опкодами декодирование и выполнение инструкций; `gminit.c`/`gminit.h` — инициализация, загрузка файла, цикл выполнения; `memory.c`/`memory.h` — работа с памятью VM, пока только работа со стеком, пока нет кучи |
| `gme/` | `gme.c` — CLI-эмулятор |
| `gasm/` | `gasm.c` — CLI ассемблера; `assembler/assembler.c`/`.h` — два прохода по файлу, метки, заголовок; `assembler/parser.c`/`.h` — разбор строк и операндов; `assembler/emit.h` — запись байтов |
| `examples/` | небольшие программы на `.gasm` |

Точки входа: `gme/gme.c` и `gasm/gasm.c`.

```text
gme/gme.c ──> gminit ──> gm.c ──> memory.c
gasm/gasm.c ──> assembler ──> parser.c
                       └───> emit.h
```

## Сборка и запуск

```sh
./build.sh --build                        # собрать build/gasm и build/gme
./build.sh --examples                     # выполнить examples/*.gasm после --build

./build/gasm examples/arith.gasm -o arith.gm
./build/gme arith.gm
```

Требуются gcc и POSIX `getline`/`strndup`.

## Соглашения вызова

ABI похож на x86_64 Linux ABI. Референс - https://refspecs.linuxbase.org/elf/x86_64-abi-0.99.pdf

| Регистр | Роль |
|---------|------|
| `r0` | возвращаемое значение |
| `r1..r8` | аргументы функции |
| `r9..r253` | общие регистры |
| `r254` (`rsp`) | указатель стека |
| `r255` (`rbp`) | указатель кадра |

Регистры r254 и r255 закреплены за rsp и rbp. Остальные регистры жестко не закреплены, то есть это соглашение между функциями, какие регистры могут меняться при вызове функций, какие не должны меняться и сохраняться вызывающей функции.

Вот пример того, как выглядит в x86_64 ABI фрейм стека с вызывающей и вызываемой функцией:


<img width="1014" height="462" alt="изображение" src="https://github.com/user-attachments/assets/517c36c2-6feb-4235-9076-7d25ef3eb37e" />


1. Вызывающая функция кладет аргументы в регистры `r0..r8`, если регистров не хватает, пушит аргументы на стек.
2. `call` кладет на стек текущий `ip`(на картинке он лежит по адресу `rbp + 8`) и делает `jump` на указанную метку.
3. `enter N` кладет текущее значение `rbp` на стек(сейчас в этом регистре база вызывающей функции). Затем  в регистр `rbp` присваивает значение `rsp`, то есть теперь в регистре `rbp` база вызываемой функции, а на стеке по этому адресу из регистра лежит предыдущее значение `rbp`, на картинке это `rbp+ 0`. После этого `rsp -= N`. `N` должен быть неотрицательным и кратным 8. Локальные переменные лежат по отрицательным смещениям от `rbp`, на картинке они обозначены как `unspecified variable size`. В `rsp` же сейчас лежит указатель на последнюю из локальных переменных.
4. Тут какая-то полезная работа функции.
5. `leave` присваивает в `rsp` указатель `rbp`, то есть указатель стека возвращается на место, где на стеке лежит указатель `previous rbp value` на картинке, при этом локальные переменные остаются на стеке, просто мы про них забываем намеренно. Потом происходит `pop rbp` - это означает что мы берем последнее значение со стека(то есть указатель на базу прошлой = вызывающей функции) и присваиваем его в регистр `rbp`, соответсвенно в `rbp` теперь снова лежит база вызывающей функции.
6. `ret` берет со стека адрес возврата и делает `jump` на него.
Таким образом, мы выполнили работу на стеке вызываемой функции и вернули управление обратно вызывающей фукнции.


`gm/memory.c` проверяет выравнивание по 8 байт и границы `[stack_base, stack_top)`. `load`/`store` адресуют только область стека;обращение вне её даёт `VM_FAULT_BAD_ADDR`.
- Стек растёт вниз. `stack_top` — исключительная граница: последний доступный байт — `stack_top - 1`, последнее валидное слово начинается с `stack_top - 8`.

## Устройство VM

- 256 регистров (`REG_COUNT`). Регистр — это `Word`:

  ```c
  typedef union {
      int64_t  i;
      double   f;
      uint64_t u;
  } Word;
  ```

- Тегов и динамической типизации нет. Тот, кто пишет программу должен держать в голове, что у него лежит в регистре - int или float. Для человека это может быть трудно, но для кодогенератора(по-простому - компилятора) это решение к лучшему.
- Целочисленная арифметика выполняется заворачивается по модулю 2^64; переполнение не является ошибкой. То есть как в C. `div_i` при делении на ноль выставляет `VM_FAULT_DIV_ZERO`(аналог SIGFPE если вы попробуете повторить это в C). `INT64_MIN / -1` даёт `INT64_MIN`(В С такое деление - UB).
- Вещественная арифметика — обычная IEEE-754. `div_f` не проверяет ноль: `1.0/0.0` даёт `inf`, `0.0/0.0` — `NaN`.
- `gminit.c` создаёт `Vm`: выделяет `mem` размером `GM_MEM_SIZE` (1 MiB),
  кладёт стек в верхнюю часть памяти (`GM_STACK_SIZE`, 64 KiB), ставит
  `rsp = rbp = stack_top`. `vm_destroy()` освобождает память.
- `vm_execute_step()` выполняет одну инструкцию, `execute_program()` крутит её
  до `halt` или ошибки.
- Все многобайтные операнды little-endian. Чтение за границей кода даёт
  `VM_FAULT_OOB`, неизвестный опкод — `VM_FAULT_BAD_OP`, переход за границы
  кода — `VM_FAULT_BAD_IP`.
- Ошибки не роняют процесс: VM выставляет `VmStatus`, цикл останавливается,
  `gme` возвращает `1`.
- Прыжки (`jmp`, `jnz`, `jz`) относительные. Смещение — знаковый `int64_t`,
  считается от байта после инструкции и кодируется 8 байтами. Цель должна
  попадать в `[0, code_len)`.

## Формат байткода

`.gm` начинается с обязательного заголовка, за которым идёт поток инструкций.
Все поля little-endian:

| Смещение | Размер | Поле | Смысл |
|----------|--------|------|-------|
| 0 | 4 | `magic` | На этом этапе можно откинуть рандомные бинарные файлы 
| 4 | 4 | `version` | Версия формата, сейчас `1`, нужна, чтобы смена формата не проходила бесследно для старых бинарников, для нас это в целом бесполезно |
| 8 | 8 | `entry` | Вот тут важно, ассемблер пытается найти метку `start` и пишет в `entry` смещение в байткоде до этой метки, или 0, если метки нет. Потом эмулятор ставит `vm->ip` на это смещение. То есть если `start` есть, выполнение начнется с него, иначе с первой инструкции|
| 16 | 8 | `code_len` | длина кода в байтах |
| 24 | — | `code` | поток инструкций |

`gminit.c` проверяет:
- файл не короче 24 байт;
- `magic` совпадает;
- `version == 1`;
- `code_len` точно равен размеру файла минус 24;
- `code_len > 0` и `entry < code_len`.

Каждая инструкция состоит из 1 байта опкода и операндов, порядок и ширины
которых задаёт сигнатура.

| Символ | Операнд | Размер |
|--------|---------|--------|
| `r` | регистр `r0..r255` | 1 байт |
| `i` | целое `int64_t` | 8 байт |
| `f` | `double` (IEEE-754 bits) | 8 байт |
| `l` | относительное смещение метки, `int64_t` | 8 байт |

| Опкод | Мнемоника | Сигнатура | Размер | Смысл |
|-------|-----------|-----------|--------|-------|
| 0 | `nop` | — | 1 | ничего не делает |
| 1 | `halt` | — | 1 | остановить VM |
| 2 | `load_i` | `ri` | 10 | `dst = i64` |
| 3 | `add_i` | `rrr` | 4 | `dst = a + b` (wrap) |
| 4 | `sub_i` | `rrr` | 4 | `dst = a - b` (wrap) |
| 5 | `mul_i` | `rrr` | 4 | `dst = a * b` (wrap) |
| 6 | `div_i` | `rrr` | 4 | `dst = a / b`, ошибка при `b == 0` |
| 7 | `cmp_lt_i` | `rrr` | 4 | `dst = a < b` (0/1) |
| 8 | `print_i` | `r` | 2 | печать `int64_t` |
| 9 | `add_f` | `rrr` | 4 | `dst = a + b` |
| 10 | `sub_f` | `rrr` | 4 | `dst = a - b` |
| 11 | `mul_f` | `rrr` | 4 | `dst = a * b` |
| 12 | `div_f` | `rrr` | 4 | `dst = a / b` (IEEE-754) |
| 13 | `cmp_lt_f` | `rrr` | 4 | `dst = a < b` (0/1 в `.i`) |
| 14 | `print_f` | `r` | 2 | печать `double` |
| 15 | `load_f` | `rf` | 10 | `dst = f64` |
| 16 | `mov` | `rr` | 3 | `dst = src` |
| 17 | `jmp` | `l` | 9 | безусловный переход |
| 18 | `jnz` | `rl` | 10 | переход, если `reg.i != 0` |
| 19 | `jz` | `rl` | 10 | переход, если `reg.i == 0` |
| 20 | `call` | `l` | 9 | положить return address и перейти |
| 21 | `ret` | — | 1 | снять return address и перейти |
| 22 | `enter` | `i` | 9 | `push rbp; rbp = rsp; rsp -= N` |
| 23 | `leave` | — | 1 | `rsp = rbp; pop rbp` |
| 24 | `push` | `r` | 2 | положить регистр на стек |
| 25 | `pop` | `r` | 2 | снять слово со стека в регистр |
| 26 | `load` | `rri` | 11 | `dst = mem[base + off]` |
| 27 | `store` | `rir` | 11 | `mem[base + off] = src` |

## Ассемблер

Синтаксис:

- одна инструкция на строку;
- операнды через запятую;
- регистры — `r0..r255` (префикс `r`/`R`, дальше десятичные цифры);
- `rsp` и `rbp` — псевдонимы `r254` и `r255` (регистр и буквы можно писать в
  любом регистре: `RSP`, `Rbp`);
- целые литералы — десятичные, в диапазоне `int64_t`;
- литералы `double` — то, что принимает `strtod` (включая `1.5`, `1e3`);
- метка — `name:` в начале строки, без пробелов внутри; может стоять на той же
  строке перед инструкцией. Ссылаться можно вперёд. Повтор метки — ошибка;
- `start:` — необязательная entry-метка. Её адрес попадает в заголовок `.gm`,
  поэтому функции можно писать до `start`, но выполнение начнется именно со start.
  Если `start` нет, точка входа — 0;
- комментариев и директив нет, `;` и `#` не поддерживаются.

Операнд `l` принимает как метку, так и целое число - смещение. После первого прохода метка заменяется на смещение.

### Два прохода

1. `collect_labels()` в `gasm/assembler/assembler.c` читает только «шапку»
   строки: необязательную метку и имя команды. Размер инструкции считается по сигнатуре, чтобы не парсить операнды, тем самым усложняя первый проход.
   Это нужно, чтобы посчитать смещения, которые подставятся вместо меток, для второго прохода, так как на втором проходе происходит выгрузка в бинарник, а функции семейства jump и call ожидают целочисленные смещения в бинарном формате.
   На этом проходе ловятся неизвестная инструкция, кривая метка и повтор метки.
3. `emit_instructions()` разбирает операнды через `parser.c`, подставляет адреса
   меток, вычисляет `int64_t`-смещение `label_addr - next_addr` и пишет байты
   через `emit.h`. Ошибки операндов (неверный регистр, число, лишний аргумент)
   появляются только здесь, с корректными номером строки и колонкой.

Перед вторым проходом `write_header()` пишет 24-байтовый заголовок. Генерация
не зависит от мнемоники: `emit_instr()` берёт сигнатуру из `InstrInfo` и
вызывает `emit_operand()` для каждого символа. Чтобы добавить новую инструкцию,
достаточно:

- добавить значение в `Opcode` и строку в `instructions[]` в
  `interface/opcodes.h`;
- добавить обработчик `case` в `vm_execute_step()` в `gm/gm.c`.

Эмиттер менять не нужно, если используется один из существующих символов
сигнатуры.

### Ограничение двух проходов

Если ошибка операнда случится на втором проходе, заголовок и часть `.gm` уже
могут быть записаны. Ошибка будет выведена, но файл в этом случае невалиден, но остаётся на диске.
Это неприятно, надо будет решить.

## Что дальше
- Нет комментариев, директив, секций, строк и `rodata`. Также есть смысл организовать const-pool
- Есть стек вызовов и фреймы, но нет кучи, массивов, строк и ввода. Память
  данных ограничена фиксированным стеком.
