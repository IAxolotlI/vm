# Gm

Gigachad machine

Данный файл сгенерен нейронкой, я уже устал описывать все конвенции, если надо разобраться в чем-то - спрашивайте напрямую

## Состав

Код разбит на модули. Общие типы и формат лежат в `interface/`, реализация VM — в
`gm/`, ассемблер — в `gasm/assembler/`, CLI — в `gme/` и `gasm/`.

| Каталог | Что внутри |
|---------|------------|
| `common/` | `sv.h` — `String_View`; `container.h` — динамический массив `da_*` и очередь `q_*`; `logger.h` — `LOG_*` и `PRINT_*` |
| `interface/` | `abi.h` — роли регистров, размеры памяти и стека; `format.h` — заголовок `.gm`; `opcodes.h` — `Opcode`, `InstrInfo` и таблица `instructions[]` |
| `gm/` | `gm.h` — `Word`, `Vm`, `VmStatus`; `gm.c` — декодирование и выполнение инструкций; `gminit.c`/`gminit.h` — инициализация, загрузка файла, цикл выполнения; `memory.c`/`memory.h` — чтение/запись памяти, `push`/`pop`, проверка адресов |
| `gme/` | `gme.c` — CLI-эмулятор |
| `gasm/` | `gasm.c` — CLI ассемблера; `assembler/assembler.c`/`.h` — два прохода, метки, заголовок; `assembler/parser.c`/`.h` — разбор строк и операндов; `assembler/emit.h` — запись байтов |
| `examples/` | небольшие программы на `.gasm` |

Точки входа: `gme/gme.c` и `gasm/gasm.c`.

```text
gme/gme.c ──> gminit ──> gm.c ──> memory.c
gasm/gasm.c ──> assembler ──> parser.c
                       └───> emit.h
```

## Сборка и запуск

```sh
./build.sh --build                        # собрать build/gasm и build/gme
./build.sh --examples                     # выполнить examples/*.gasm после --build

./build/gasm examples/arith.gasm -o arith.gm
./build/gme arith.gm
```

Требуются gcc и POSIX `getline`/`strndup`.

## Соглашения вызова

ABI описан в `interface/abi.h`:

| Регистр | Роль |
|---------|------|
| `r0` | возвращаемое значение |
| `r1..r8` | аргументы функции |
| `r9..r253` | общие регистры |
| `r254` (`rsp`) | указатель стека |
| `r255` (`rbp`) | указатель кадра |

Все регистры, включая `r0..r8`, считаются caller-saved: вызываемая функция
может их менять. Отдельных callee-saved регистров нет. VM не проверяет
соблюдение ABI — это соглашение программ, а не свойство интерпретатора.

- `call` кладёт на стек абсолютный адрес возврата и переходит по метке.
- `ret` снимает адрес возврата и переходит по нему.
- `enter N` делает `push rbp`, затем `rbp = rsp`, затем `rsp -= N`.
  `N` должен быть неотрицательным и кратным 8. Локальные переменные лежат по
  отрицательным смещениям от `rbp`.
- `leave` делает `rsp = rbp` и `pop rbp`.
- `push`/`pop` работают с одним 8-байтовым словом.
- Стек растёт вниз. `stack_top` — исключительная граница: последний доступный
  байт — `stack_top - 1`, последнее валидное слово начинается с
  `stack_top - 8`.

`gm/memory.c` проверяет выравнивание по 8 байт и границы
`[stack_base, stack_top)`. `load`/`store` адресуют только область стека;
обращение вне её даёт `VM_FAULT_BAD_ADDR`.

## Устройство VM

- 256 регистров (`REG_COUNT`). Регистр — это `Word`:

  ```c
  typedef union {
      int64_t  i;
      double   f;
      uint64_t u;
  } Word;
  ```

- Тегов и динамической типизации нет. Тип значения определяется инструкцией:
  `*_i` читает и пишет `.i`, `*_f` — `.f`. `mov` копирует `Word` целиком, без
  преобразования. `print_i` читает `.i`, `print_f` — `.f`; смешивать типы и
  операции нельзя.
- `bool` — это обычный `int64_t` со значениями `0`/`1`. `cmp_lt_i` и
  `cmp_lt_f` всегда пишут результат в `.i`, а `jnz`/`jz` читают `.i`.
- Целочисленная арифметика (`add_i`, `sub_i`, `mul_i`) выполняется над
  `uint64_t` и заворачивается по модулю 2^64; переполнение не является ошибкой.
  `div_i` при делении на ноль выставляет `VM_FAULT_DIV_ZERO`, а
  `INT64_MIN / -1` даёт `INT64_MIN`.
- Вещественная арифметика — обычная IEEE-754. `div_f` не проверяет ноль:
  `1.0/0.0` даёт `inf`, `0.0/0.0` — `NaN`.
- `print_i` печатает `int64_t` через `PRId64`, `print_f` — `double` через `%g`;
  обе добавляют `\n`.
- `gminit.c` создаёт `Vm`: выделяет `mem` размером `GM_MEM_SIZE` (1 MiB),
  кладёт стек в верхнюю часть памяти (`GM_STACK_SIZE`, 64 KiB), ставит
  `rsp = rbp = stack_top`. `vm_destroy()` освобождает память.
- `vm_execute_step()` выполняет одну инструкцию, `execute_program()` крутит её
  до `halt` или ошибки. `gm.c` не знает про файлы и CLI.
- Все многобайтные операнды little-endian. Чтение за границей кода даёт
  `VM_FAULT_OOB`, неизвестный опкод — `VM_FAULT_BAD_OP`, переход за границы
  кода — `VM_FAULT_BAD_IP`.
- Ошибки не роняют процесс: VM выставляет `VmStatus`, цикл останавливается,
  `gme` возвращает `1`.
- Прыжки (`jmp`, `jnz`, `jz`) относительные. Смещение — знаковый `int64_t`,
  считается от байта после инструкции и кодируется 8 байтами. Цель должна
  попадать в `[0, code_len)`.

## Формат байткода

`.gm` начинается с обязательного заголовка, за которым идёт поток инструкций.
Все поля little-endian:

| Смещение | Размер | Поле | Смысл |
|----------|--------|------|-------|
| 0 | 4 | `magic` | `'G' 'M' 0 0` |
| 4 | 4 | `version` | версия формата, сейчас `1` |
| 8 | 8 | `entry` | смещение точки входа от начала кода |
| 16 | 8 | `code_len` | длина кода в байтах |
| 24 | — | `code` | инструкции |

Ассемблер ищет метку `start` и записывает её адрес в `entry`. Если `start` нет,
`entry = 0`. Эмулятор ставит `ip = entry`.

`gminit.c` проверяет:

- файл не короче 24 байт;
- `magic` совпадает;
- `version == 1`;
- `code_len` точно равен размеру файла минус 24;
- `code_len > 0` и `entry < code_len`.

Файлы без заголовка (сырой байткод) сейчас не поддерживаются: при несовпадении
`magic` `vm->code` не выставляется, и выполнение сразу заканчивается
`VM_FAULT_OOB` с `code_len = 0`. Отдельной диагностики «нет magic» нет.

Каждая инструкция состоит из 1 байта опкода и операндов, порядок и ширины
которых задаёт сигнатура.

| Символ | Операнд | Размер |
|--------|---------|--------|
| `r` | регистр `r0..r255` | 1 байт |
| `i` | целое `int64_t` | 8 байт |
| `f` | `double` (IEEE-754 bits) | 8 байт |
| `l` | относительное смещение метки, `int64_t` | 8 байт |

| Опкод | Мнемоника | Сигнатура | Размер | Смысл |
|-------|-----------|-----------|--------|-------|
| 0 | `nop` | — | 1 | ничего не делает |
| 1 | `halt` | — | 1 | остановить VM |
| 2 | `load_i` | `ri` | 10 | `dst = i64` |
| 3 | `add_i` | `rrr` | 4 | `dst = a + b` (wrap) |
| 4 | `sub_i` | `rrr` | 4 | `dst = a - b` (wrap) |
| 5 | `mul_i` | `rrr` | 4 | `dst = a * b` (wrap) |
| 6 | `div_i` | `rrr` | 4 | `dst = a / b`, ошибка при `b == 0` |
| 7 | `cmp_lt_i` | `rrr` | 4 | `dst = a < b` (0/1) |
| 8 | `print_i` | `r` | 2 | печать `int64_t` |
| 9 | `add_f` | `rrr` | 4 | `dst = a + b` |
| 10 | `sub_f` | `rrr` | 4 | `dst = a - b` |
| 11 | `mul_f` | `rrr` | 4 | `dst = a * b` |
| 12 | `div_f` | `rrr` | 4 | `dst = a / b` (IEEE-754) |
| 13 | `cmp_lt_f` | `rrr` | 4 | `dst = a < b` (0/1 в `.i`) |
| 14 | `print_f` | `r` | 2 | печать `double` |
| 15 | `load_f` | `rf` | 10 | `dst = f64` |
| 16 | `mov` | `rr` | 3 | `dst = src` |
| 17 | `jmp` | `l` | 9 | безусловный переход |
| 18 | `jnz` | `rl` | 10 | переход, если `reg.i != 0` |
| 19 | `jz` | `rl` | 10 | переход, если `reg.i == 0` |
| 20 | `call` | `l` | 9 | положить return address и перейти |
| 21 | `ret` | — | 1 | снять return address и перейти |
| 22 | `enter` | `i` | 9 | `push rbp; rbp = rsp; rsp -= N` |
| 23 | `leave` | — | 1 | `rsp = rbp; pop rbp` |
| 24 | `push` | `r` | 2 | положить регистр на стек |
| 25 | `pop` | `r` | 2 | снять слово со стека в регистр |
| 26 | `load` | `rri` | 11 | `dst = mem[base + off]` |
| 27 | `store` | `rir` | 11 | `mem[base + off] = src` |

Опкод `load_f` имеет значение `15`, хотя в таблице `instructions[]` стоит рядом
с остальными `_f`-инструкциями. Порядок строк в таблице не обязан совпадать с
порядком значений enum.

## Ассемблер

Синтаксис:

- одна инструкция на строку;
- операнды через запятую;
- регистры — `r0..r255` (префикс `r`/`R`, дальше десятичные цифры);
- `rsp` и `rbp` — псевдонимы `r254` и `r255` (регистр и буквы можно писать в
  любом регистре: `RSP`, `Rbp`);
- целые литералы — десятичные, в диапазоне `int64_t`;
- литералы `double` — то, что принимает `strtod` (включая `1.5`, `1e3`);
- метка — `name:` в начале строки, без пробелов внутри; может стоять на той же
  строке перед инструкцией. Ссылаться можно вперёд. Повтор метки — ошибка;
- `start:` — необязательная entry-метка. Её адрес попадает в заголовок `.gm`,
  поэтому функции можно писать до `start` и не ставить `jmp` в начало файла.
  Если `start` нет, точка входа — 0;
- комментариев и директив нет, `;` и `#` не поддерживаются.

Операнд `l` принимает как метку, так и целое число. Число используется как
готовое относительное смещение; метка заменяется смещением на втором проходе.

### Два прохода

1. `collect_labels()` в `gasm/assembler/assembler.c` читает только «шапку»
   строки: необязательную метку и мнемонику. Операнды не разбираются. Размер
   инструкции считается по сигнатуре (`OPCODE_SIZE + сумма ширин`), поэтому
   `pc` и адреса меток известны без знания значений операндов. На этом проходе
   ловятся неизвестная мнемоника, кривая метка и повтор метки.
2. `emit_instructions()` разбирает операнды через `parser.c`, подставляет адреса
   меток, вычисляет `int64_t`-смещение `label_addr - next_addr` и пишет байты
   через `emit.h`. Ошибки операндов (неверный регистр, число, лишний аргумент)
   появляются только здесь, с корректными номером строки и колонкой.

Перед вторым проходом `write_header()` пишет 24-байтовый заголовок. Генерация
не зависит от мнемоники: `emit_instr()` берёт сигнатуру из `InstrInfo` и
вызывает `emit_operand()` для каждого символа. Чтобы добавить новую инструкцию,
достаточно:

- добавить значение в `Opcode` и строку в `instructions[]` в
  `interface/opcodes.h`;
- добавить обработчик `case` в `vm_execute_step()` в `gm/gm.c`.

Эмиттер менять не нужно, если используется один из существующих символов
сигнатуры.

### Ограничение двух проходов

Если ошибка операнда случится на втором проходе, заголовок и часть `.gm` уже
могут быть записаны. Файл в этом случае невалиден, но остаётся на диске.

## Известные ограничения

- Заголовок есть, но нет контрольной суммы, таблицы символов и дизассемблера.
  `gme` валидирует magic/version/длину/entry, но не проверяет каждую
  инструкцию до запуска.
- Нет комментариев, директив, секций, строк и `rodata`.
- Есть стек вызовов и фреймы, но нет кучи, массивов, строк и ввода. Память
  данных ограничена фиксированным стеком.
- Сырой байткод без заголовка не поддерживается.
- Нет неявного `halt`: программа без `halt` дочитывает код до конца и падает в
  `VM_FAULT_OOB` уже после выполнения полезной части.
- Типобезопасность держится на соглашении: инструкция `*_i` и `print_i`
  читают `.i`, `*_f` и `print_f` — `.f`. `mov` не преобразует тип. Прочитать
  значение не тем опкодом можно без ошибки — получится интерпретация тех же
  битов как другого типа.
- Целочисленная арифметика заворачивается, отдельного `VM_FAULT_OVERFLOW` нет.
- Нет тестов, CI, make/cmake.
- `getline` и `strndup` — POSIX/GNU, не C11; под MSVC не соберётся.

## Магические числа и константы

- **`REG_COUNT = 256`** (`interface/opcodes.h`) — число регистров. Номер
  регистра кодируется одним байтом, поэтому 256 — это весь диапазон
  `r0..r255`.
- **Значения опкодов `0..27`** (`Opcode` в `interface/opcodes.h`) — часть
  формата файла, а не просто enum. Менять существующие значения нельзя, не
  сломав уже собранные `.gm`; новые опкоды добавляйте в конец.
- **Ширины `1` и `8` байт** (`REG_SIZE`, `OPCODE_SIZE`, `INT_SIZE`,
  `FLOAT_SIZE` в `interface/opcodes.h`) — 1 байт на опкод и регистр, 8 байт на
  `int64_t`, `double` и смещение метки. Для `'l'` используется `INT_SIZE`,
  отдельной константы нет. Все многобайтные числа little-endian; порядок байт —
  часть формата.
- **`GM_HEADER_SIZE = 24`, `GM_FORMAT_VERSION = 1`** (`interface/format.h`) —
  размер заголовка и текущая версия формата.
- **`GM_MEM_SIZE = 1 MiB`, `GM_STACK_SIZE = 64 KiB`, `GM_STACK_ALIGN = 8`,
  `GM_STACK_MIN = 16`** (`interface/abi.h`) — размеры памяти и стека, шаг
  выравнивания и минимальный размер стека.
- **Коды возврата** — `0` при успехе, `1` при любой ошибке (`gasm`/`gme`).
- **`DA_INIT_CAP = 128`** и **`Q_INIT_CAP = 128`** (`common/container.h`) —
  начальные ёмкости динамического массива и очереди; на формат файла не влияют.
- **Поле `Word.u`** используется для `rsp`/`rbp`, адресов, `push`/`pop` и
  `load`/`store`.
